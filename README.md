# Real Rex

**Send your five best spots.**

Right now, recommending places to a friend means opening Google Maps, digging
through starred places, copying links one at a time, and pasting them into
WhatsApp. It is high friction, and the result is bad: a list of seventy-five
pins nobody will ever read.

Real Rex takes the opposite bet. **A list holds a maximum of five spots.** Not
as a limitation — as the product. If a friend sends you their five places in
Barcelona, they are probably all worth going to.

Your lists are for your network. They are not for public parading.

---

## Status

Early. The scaffolding is in place; the app is not built yet.

## How it works

- You keep a personal **library** of spots, added by pasting a Google Maps link.
- A **list** is a selection of up to five spots toggled on from that library, so
  one spot can appear on several lists.
- Publishing a list gives you a URL. You send that link to a friend. They open a
  web page — **no account, no app install, no signup wall.**

Example lists: _My top Barcelona spots_, _Places you can still get an espresso
for less than €1_, _Laptop cafes_.

## Stack

| Layer                   | Choice                                                     |
| ----------------------- | ---------------------------------------------------------- |
| Mobile                  | Expo (React Native), expo-router, TypeScript               |
| Web                     | Next.js App Router on Vercel — hosts the public list pages |
| Backend                 | Supabase (Postgres, Auth, Row Level Security)              |
| Analytics, errors, logs | PostHog (EU cloud)                                         |
| Repo                    | npm workspaces monorepo, no task runner                    |

Every one of these choices, and the alternatives rejected, is written down in
[`docs/decisions.md`](docs/decisions.md).

## Repository layout

```
apps/
  mobile/      Expo app
  web/         Next.js app — public list pages and marketing
packages/
  shared/      Types, constants and pure helpers used by both apps
supabase/
  migrations/  The database schema. The only source of truth.
docs/          Architecture and decision records
```

`packages/shared` exists for one reason above all others: `supabase gen types`
generates a `database.types.ts` that both apps must use _identically_. Copying
that file between two repositories is a bug factory.

## Getting started

**Prerequisites**

|        | version               | why                         |
| ------ | --------------------- | --------------------------- |
| Node   | 22+                   | see `.nvmrc`                |
| npm    | 10+                   | workspaces                  |
| Docker | any recent            | local Supabase stack        |
| Xcode  | **26.4+ (Swift 6.3)** | iOS builds only — see below |

Expo SDK 57 will **not compile on Xcode below 26.4**. It fails inside
`expo-modules-jsi` with `'RuntimeScheduler' cannot be annotated with
SWIFT_RETURNS_RETAINED`, which looks like an Expo bug but is simply a Swift
compiler too old to understand the annotation. Check with
`xcodebuild -version`.

```bash
git clone git@github.com:charcarr/real-rex.git
cd real-rex
npm install

# Start the local database. Studio is at http://localhost:54323
npm run db:start
npm run db:types          # regenerate TypeScript types from the schema

cp apps/web/.env.example apps/web/.env.local
cp apps/mobile/.env.example apps/mobile/.env
# fill in the values printed by `npm run db:start`

npm run web               # Next.js at http://localhost:3000
```

### Running the mobile app

Real Rex uses an Expo **development build**, not Expo Go. The first run compiles
a native app and installs it on the simulator — this takes 5–10 minutes and
needs Xcode. You only do it once.

```bash
npm run ios               # compiles and installs the development build
```

After that, day to day:

```bash
npm run mobile            # starts the dev server; JS changes hot-reload
```

Rebuild with `npm run ios` only when a **native** dependency or native config
changes. Pure JavaScript and TypeScript changes never need it.

`ios/` and `android/` are generated by `expo prebuild` and are deliberately not
checked in. `app.json` plus config plugins are the source of truth. Run
`npm run prebuild --workspace @real-rex/mobile` to regenerate them.

### Working on the database

Design visually in the **local** Supabase Studio, then capture what you did:

```bash
npm run db:diff -- add_lists   # writes supabase/migrations/<timestamp>_add_lists.sql
```

Never click in production. The migrations directory is the source of truth.
